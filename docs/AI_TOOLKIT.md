# AI 툴킷

에이전트(Claude Code·Codex·Cursor 등)가 이 SDK로 일할 때 읽는 자산을 SDK가 소유하고 배포합니다.

## 1. 무엇인가

템플릿 프로젝트에서 에이전트에게 일을 시키려면 에이전트가 "이 SDK가 무엇이고 무엇을 하면 안 되는지"를
알아야 합니다. 그 지식을 프로젝트마다 손으로 적어 두면 SDK가 올라갈 때마다 낡습니다. AI 툴킷은 그
지식을 **SDK 쪽 자산**으로 두고, `bstage ai` 명령이 프로젝트에 설치·동기화합니다.

**MCP 서버가 아닙니다.** 프로세스도 네트워크 연결도 없습니다. 파일을 몇 개 쓰는 것이 전부이며,
에이전트는 그 파일을 평소처럼 읽습니다.

## 2. 설치되는 파일

| 파일                                    | 무엇인가                                                         | 갱신 규칙                                                       |
| --------------------------------------- | ---------------------------------------------------------------- | --------------------------------------------------------------- |
| `AGENTS.md`                             | 프로젝트 규칙·SDK 사용 규약. 관리 영역 마커로 감싼 부분만 SDK 것 | 관리 영역만 덮어씁니다. 마커 바깥 자유 영역은 보존합니다        |
| `CLAUDE.md`                             | `AGENTS.md`를 가리키는 한 줄 포인터                              | **없을 때만** 만듭니다. 있으면 내용과 무관하게 손대지 않습니다  |
| `.claude/skills/<이름>/SKILL.md`        | 작업별 절차서. 아래 kind별 세트                                  | SDK 소유입니다. 스탬프 버전이 다르면 통째로 다시 씁니다         |
| `.husky/pre-commit`·`check-secrets.mjs` | 커밋 전 시크릿 가드                                              | 가드 스크립트는 덮어쓰고, 기존 훅이 있으면 실행 줄만 덧붙입니다 |

스킬 세트는 프로젝트 종류(kind)로 갈립니다.

| kind     | 설치되는 스킬                                                                |
| -------- | ---------------------------------------------------------------------------- |
| `sdk`    | `bstage-template` · `bstage-migrate` · `bstage-onboarding` · `bstage-deploy` |
| `liquid` | `bstage-liquid` · `bstage-migrate` · `bstage-onboarding` · `bstage-deploy`   |

kind는 레포의 **파일 구조**로 판정합니다. `public/{user|admin}/{이름}/template.liquid`가 하나 이상이면
liquid, liquid 파일이 없고 `src/pages|slots/**/template.tsx`가 있거나 SDK 패키지를 의존하면 sdk입니다.
템플릿 파일이 **양쪽 다** 있으면 `mixed`이고, 포털이 빌드하지 못하므로 명령이 종료 코드 2로 멈춥니다.
의존성만으로는 mixed가 되지 않습니다 — liquid 파일이 있으면 `@bstage-sdk/cli`를 의존해도
liquid입니다(liquid 스캐폴드도 저작 도구로 CLI를 씁니다).

## 3. 어느 도구가 무엇을 읽나

- **`AGENTS.md`** — Codex·Cursor·Copilot 등 대부분의 코딩 에이전트가 공통으로 읽는 관례 파일입니다.
- **`.claude/skills/`** — Claude Code가 자동으로 인식합니다.

다른 도구 전용 규칙 파일(예: `.cursor/rules`)이 필요하면, 내용을 복제하지 말고 `AGENTS.md`를 가리키는
한 줄짜리 파일을 직접 두세요. 복제본은 SDK가 갱신하지 않으므로 반드시 낡습니다.

## 4. 명령

| 명령                | 하는 일                                                                     |
| ------------------- | --------------------------------------------------------------------------- |
| `bstage ai install` | 없는 파일은 만들고 낡은 파일은 갱신 + pre-commit 시크릿 가드 설치           |
| `bstage ai update`  | **이미 있는** 파일만 갱신. 없는 파일은 만들지 않고 가드도 건드리지 않습니다 |
| `bstage ai doctor`  | 상태만 진단(파일 수정 없음). `--json` 지원                                  |

- 새 프로젝트는 `bstage init`이 이미 설치해 둡니다 — `install`을 다시 돌릴 필요가 없습니다.
- SDK를 올린 뒤에는 `update`를 돌립니다. "최신화"를 부른 사람이 새 파일이 생기는 것을 기대하지 않기
  때문에 `update`는 생성을 하지 않습니다. 없는 파일이 있으면 `install`로 안내합니다.
- 셋 다 `--dir <경로>`(기본 `.claude/skills`)와 `--kind sdk|liquid`를 받습니다. `--kind`는 자동 판정이
  실패할 때의 보조 수단이며, 판정 결과와 어긋나면 덮어쓰지 않고 멈춥니다.
- `bstage skills install`은 `bstage ai install`의 **deprecated 별칭**입니다. 경고를 출력하고 같은 일을
  하며 다음 릴리즈에서 제거됩니다.
- `bstage doctor`는 진단에 더해 **SDK 소유 스킬만** 자동 동기화합니다. `package.json`과 `.husky`는
  건드리지 않으므로, pre-commit 시크릿 가드는 `bstage ai install`로 설치하세요.

`doctor`의 종료 코드는 전부 최신이면 0, 하나라도 어긋나면 2입니다. 상태 값은 `ok` · `stale` · `missing` ·
`extra`이며, **`extra`(지금 kind에 속하지 않는 SDK 스킬이 남아 있음)는 경고일 뿐 종료 코드에 영향을 주지
않습니다.** 설치가 남의 파일을 지우지 않는 것이 설계라, 실패로 치면 사람이 손으로 지울 때까지 CI가 계속
빨간불이 되기 때문입니다.

## 5. 처음 시작하는 법

프로젝트가 아직 없다면 에이전트에게 이렇게 말하는 것으로 충분합니다.

> 이 프로젝트를 처음 만드는데, 포털에 올리는 것까지 도와줘.

`bstage-onboarding` 스킬이 받아서 진행합니다.

1. 결정 세 가지(유저·어드민 / React·liquid / 배포 환경)를 한 번에 묻고 나머지 확인은 에이전트가 합니다.
2. 프로젝트 생성 → 로컬 실행 → 커밋·push → 포털 연결(`bstage link`) → 첫 배포(`bstage deploy`) 순서로
   단계마다 **성공 판정 기준을 먼저 말하고** 확인합니다.
3. 되돌리기 어려운 일(원격 push·배포·게시 전환)은 실행 전에 보여 주고 확인을 받습니다.

배치(어느 페이지·어느 자리에 템플릿을 켤지)를 만들거나 지우는 일은 **포털 화면에서만** 합니다. CLI도
에이전트도 하지 않습니다.

## 6. 갱신 규칙

- **스킬 파일은 SDK 소유입니다.** 손으로 고쳐도 다음 갱신에 덮어쓰입니다. 프로젝트 고유 규칙은
  `AGENTS.md` 자유 영역에 적으세요.
- **`AGENTS.md`는 관리 영역만 덮습니다.** 마커(`BSTAGE:MANAGED:START`~`END`) 바깥은 그대로 둡니다.
  관리 영역 안의 프로젝트 정체성(스페이스·프로젝트명)은 기존 파일 값을 우선합니다.
- **마커가 없는 레거시 `AGENTS.md`는 자동으로 건드리지 않습니다.** 어디까지가 SDK 것인지 알 수 없어
  덮어쓰면 사용자 내용을 잃기 때문입니다. `bstage-migrate` 스킬이 실제 파일을 읽고 reconcile합니다.
- `CLAUDE.md`는 포인터일 뿐이고 그 뒤는 사용자 것이므로, 있으면 내용 불문 손대지 않습니다.

## 7. 예정

포털 측 MCP 서버가 생기면 `bstage ai install`이 그 클라이언트 설정도 함께 놓을 자리입니다.
